## 프로젝트 맥락

대형 행사 뒤 이동 시간이 평소보다 길어진 경험에서 시작한 개인 프로젝트입니다. 단순히 사람이 많이 모였다는 설명에서 멈추지 않고, 이동 수요와 대중교통 공급 proxy를 함께 확인했습니다. 교내 데이터 분석 프로젝트 우수상을 받았습니다.

## 분석 문제

여의도 불꽃축제 당일의 수요는 언제, 어느 방향에 집중됐는가? 관측된 수요와 이동시간의 관계를 실제 운영 검토에 쓸 수 있는 차량 규모로 어떻게 바꿀 수 있는가?

초기 졸업 연구는 2023년 10월 7일 행사일과 6개 비행사 일요일을 비교했습니다. 당시 노트북에는 비교일을 토요일로 적었지만 날짜를 다시 확인한 결과 모두 일요일이었습니다. 따라서 공개본은 이 차이를 인과적인 행사 효과가 아니라 탐색적 주말 참고선으로 다룹니다.

## 방법

| 판단 | 적용한 방법 | 이유 |
|---|---|---|
| 데이터 결합 검증 | bbox, 정류장명, stop list, route master, TPSS와 GIS encoding 재확인 | 초기 정류장 ID matching coverage가 약 `26.7%`여서 모델보다 결합 품질을 먼저 고쳤습니다. |
| 참고선 구성 | 비행사 날짜별 집계 후 평균 | 특정 날짜의 관측량이 참고선을 지배하지 않게 했습니다. |
| 수요와 현장 집중 확인 | OD와 체류인구를 같은 시간 단위로 정리 | 이동 방향과 현장 집중 시간을 함께 보기 위해서입니다. |
| 이동시간 요약 | 이동량 가중평균 | 통행량이 다른 OD 행을 단순 평균하지 않기 위해서입니다. |
| 지체 관계 추정 | Isotonic regression | 초과 교통량이 증가할 때 예측 지체가 감소하지 않게 하면서 증가 폭은 데이터에 맡겼습니다. |
| 성능 검증 | 날짜 전체를 제외하는 교차검증 | 같은 날짜의 관측치가 학습과 평가에 함께 들어가는 누수를 막았습니다. |

Isotonic regression은 교통량과 지체의 인과관계를 증명하지 않습니다. 같은 OD·수단끼리 비교해야 이동 구성 변화와 지체를 더 정확히 분리할 수 있습니다. 초기 노트북에서 확인한 오류와 수정 내용은 [노트북 검토 기록](docs/NOTEBOOK_AUDIT.md)에 있습니다.

## 분석의 활용

원 연구에서는 수요 증가와 대중교통 공급 proxy 감소가 함께 나타나는지를 탐색했고, 결과를 모든 목적지로 직접 운행하는 노선 대신 공덕·당산·노량진 환승거점까지 연결하는 셔틀 시나리오로 바꿨습니다.

당시 약 13,000명의 추가 수요를 차량 규모 산정의 입력으로 사용했습니다. `45석 × 100대 × 3회전 = 13,500명`은 수송 가능 규모를 비교한 산술 시나리오이며, 현재 공개된 합성 pipeline에서 다시 산출한 결과는 아닙니다. 배차, 도로 운영과 비용 효과를 검증한 simulation도 아닙니다.

## 공개 범위와 실행

원본 OD·체류인구 데이터는 이용 조건과 용량 문제로 배포하지 않습니다. 공개본은 초기 탐색 코드를 전처리, 비교, 날짜 단위 검증과 시나리오 함수로 나눴고, 같은 열 구조의 합성 sample로 실행 흐름을 확인합니다.

```bash
python -m pip install -e ".[dev]"
pytest
python scripts/run_sample_analysis.py
```

실행 결과는 `results/sample/`에 표와 그림으로 저장됩니다. 아래 그림은 코드 경로를 확인하기 위한 합성 예시이며 실제 축제 결과나 모델 성능이 아닙니다.

## 해석 범위

- 행사일 한 번의 관측만으로 일반적인 행사 효과를 추정할 수 없습니다.
- 행사일은 토요일이고 참고일은 일요일이라 요일 차이가 섞여 있습니다.
- 참고일의 날씨, 도로 통제와 다른 행사는 현재 공개 데이터에서 통제하지 못했습니다.
- 시간대별 평균 이동시간에는 출발지 구성 변화가 섞일 수 있습니다.
- Isotonic regression은 단조 관계를 표현하지만 인과 효과를 추정하지 않습니다.
- 공개 sample은 코드 검증용 합성 데이터입니다.
- 셔틀 계산은 수송 가능 규모를 비교하는 산술 시나리오입니다.

남은 검증 항목은 [후속 분석 계획](docs/LEARNING_ROADMAP.md)에 있습니다.

## 기여

실생활에서 느낀 이동 불편을 분석 질문으로 바꾸고, 원천 데이터 선택과 결합, 정류장 matching 재검산, 시간대별 비교, 단조 제약 모델, 환승거점과 차량 규모 산정까지 진행했습니다. 공개본에서는 초기 탐색 코드를 함수와 테스트 단위로 다시 나누고, 재현할 수 있는 범위와 아직 검증하지 못한 주장을 분리했습니다.
